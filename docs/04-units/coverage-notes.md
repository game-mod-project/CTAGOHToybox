## 수기 메모

2026-10-11, 게임 버전 1.0.6.7 기준.

### 왕복 검사에 실패한 파일

`set/multiplayer/units/early/units_eng.set` 하나다. 원본에 닫는 괄호가 네 군데 남는다. 예를 들어 `squad_rec_mc_early_all`을 정의하는 매크로 호출이 `t()))`로 끝난다. 파서 문제가 아니라 파일 자체의 오류다. 이 파일은 키 목록에는 들어가지만(읽을 수 있는 데까지 읽음) 유닛 카탈로그에서는 빠진다. 게임이 이 파일을 어떻게 처리하는지는 확인하지 않았다.

### 펼치지 못한 구문

`entity/-vehicle/ussr/tank_light/zis30/zis30.def`의 `%door2` 하나다. 매크로 본문이 `%door2`를 쓰는데 호출하는 쪽이 그 인자를 주지 않는다. 원본의 누락으로 보인다.

처음 실행에서는 27개 파일이 `properties/shadow/round.inc`와 `tank.inc`를 찾지 못했다. 두 파일은 pak 안에 0바이트로 들어 있었고 추출기가 빈 파일을 건너뛰어서 생긴 문제였다. 범위 안의 빈 파일도 추출하도록 고친 뒤 해소됐다.

### 추론한 규칙의 검증 결과

| 규칙 | 결과 |
|---|---|
| 가상 경로 = pak의 폴더 + pak 안의 경로 | 맞음. `/`로 시작하는 include가 전부 풀렸다 |
| 상대 include는 그 파일의 폴더 기준 | 맞음. `ability.inc`, 차량 폴더의 `.ext`가 전부 풀렸다 |
| 조상 폴더의 `.presets`는 암묵적으로 로드된다 | 맞는 것으로 보임. 아이템 2,727개에서 풀리지 않은 매크로가 0개 |
| 매크로 인자는 `이름(값)` → `%이름`, `args a b` → `%0 %1` | 맞는 것으로 보임. 풀리지 않은 `%` 매개변수가 1개(위의 zis30) |
| 블록 주석 `/* */`는 없다 | 맞음. 그렇게 가정하고도 왕복 실패가 1개뿐 |
| 문자열 이스케이프는 없다 | 맞음. 같은 근거 |

"맞는 것으로 보임"은 풀리지 않은 것이 없다는 뜻이지 엔진이 같은 순서와 범위로 처리한다는 증명이 아니다. 예를 들어 `.presets`가 하위 폴더에까지 적용되는지, 같은 이름의 매크로가 여러 번 정의되면 어느 쪽이 쓰이는지는 구분해 확인하지 못했다. 이 구현은 나중 정의가 이긴다.

### 같은 가상 경로의 충돌

유닛 범위 안에서 같은 가상 경로를 가진 파일은 없었다(`duplicate` 0, `collision` 0).

### 키 경로를 묶은 규칙

이름이 따옴표 문자열인 블록은 경로에서 `"*"`로 묶고 이름을 값에 남겼다. 묶지 않으면 공용 그룹의 키가 60,332개가 되는데 대부분 유닛 이름이나 텍스처 경로 같은 데이터다. 묶은 뒤 11,281개다. 이름은 `units-*.jsonl.gz`의 값에 그대로 있으므로 잃은 정보는 없다.

### 의미를 살펴본 범위

사람이 등급을 매긴 것은 `data/annotations/common.psv`의 항목이다. 펼친 뒤의 키 가운데 유닛 종류별로 파일의 5% 이상에 나오는 434개를 모두 포함한다. `*/이름` 형식의 주석은 유닛 파일과 펼친 키에만 적용했다. 공용 설정이나 모델 파일에는 같은 이름이 다른 뜻으로 쓰일 수 있어서다.

"확인" 등급의 근거는 게임 파일에 개발자가 남긴 주석이다. 주석이 오래되어 현재 동작과 다를 가능성은 배제하지 못한다.
