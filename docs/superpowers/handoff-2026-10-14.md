## 미뤄 둔 지적 (Minor)

4단계 리뷰:

- `CheckEdits`가 빌드보다 덜 엄격하다. `CheckNewValue`, 인코딩, 출력 경로 충돌을 보지 않는다.
- `KeyAnnotations`의 `*/이름` 주석이 유닛이 아닌 파일을 유닛처럼 열 때도 붙는다.
- 요약 캐시가 종류로만 묶인다. 종류가 없는 파일들은 첫 그룹의 키를 쓴다.
- `CheckEdits`가 새로 그릴 때마다 '이 유닛만' 수정의 유닛을 다시 펼친다. 수정이 많으면 느릴 수 있다(재지 않았다).
- 같은 '전부' 자리를 두 번 넣는 경우의 테스트가 없다.

사용성 리뷰:

- 꺼진 수정은 수정 목록 제목에 줄 값(`[mine m1a1 24]`)이 붙지 않는다(`CheckEdits`가 켜진 것만 본다).
- 매크로 호출 줄에는 부위 문맥이 붙지 않는다.
- 요약·전체 탭의 묶음을 펼치고 접은 상태가 수정할 때마다 처음으로 돌아간다.
- `DisplayNames.FromGame`이 깨진 현지화 pak에서 예외를 낸다. 그러면 세션 열기가 실패한다.
- `editor/summary/*.psv`의 각 키가 실제 원본에서 한 줄 이상 맞는지 보는 `-- real` 검사가 없다.

3단계 리뷰:

- `IncludeChain.CopySet`이 `Reachable`을 부를 때마다 인접 목록을 다시 만든다.

2단계 리뷰의 남은 것(`handoff-2026-10-13.md`에서 넘어온 것):

- CLI에 수정을 지우는 명령이 없다. 앱에는 있다.
- 따옴표 이름 블록은 "몇 번째"로만 구분된다. 원본이 갱신돼 순서가 밀리면 다른 항목을 가리킬 수 있다.
- `CLAUDE.md`에는 "PowerShell 7"로만 적혀 있지만 도구는 .NET 8 SDK와 pwsh 7.4 이상을 요구한다.

## 사용자의 작업 원칙 (메모리에도 있다)

- **추정 금지**: 게임·모드 동작은 데이터(게임 파일, `game.log`, 모드 구성)와 리서치로 근거를 찾은 것만 사실로 말한다. 못 찾으면 "미확인"으로 적는다.
- **게임 안 확인은 몰아서**: 조사용 변경은 하나씩 부탁하지 않는다. 관련된 미확인을 한 빌드에 모아, 항목마다 다른 유닛과 다른 값을 쓴다.
- **앱을 반복해 띄우지 않는다**: 화면 확인은 `--shots <목록 파일>`로 한 번 실행에 여러 장을 찍고, 바뀐 화면만 본다.
- **문제는 내가 먼저 찾는다**: 화면을 넘기기 전에 사용자 입장에서 전 화면을 점검한다. 볼 것은 이름이 보이는지, 잘리는 글자, 내부 코드·ID 노출, 반복, 빈 상태 안내다.

## 작업 중 알게 된 것

- Git Bash에서 CLI에 `/extender...` 같은 키 경로를 넘길 때는 `MSYS_NO_PATHCONV=1`을 붙인다. 붙이지 않으면 Windows 경로로 바뀐다.
- `git add editor`를 하면 추적하지 않는 `editor/projects/ingame-check*.json`까지 들어간다. 경로를 골라서 add한다.
- 게임을 Steam 없이 켜면 창작마당 모드를 찾지 못한다(`Found 2 available mods`). 그때는 `offline` 프로필을 쓴다.
- 이 PC에는 Python이 없다. 스크립트는 pwsh나 bash로 쓴다.
- C# 코드를 perl 치환으로 넣으면 `\\` 이스케이프가 깨진다. 여러 줄 C#은 Edit/Write 도구로 넣는다.
- 앱 스크린샷 함수는 창 템플릿의 맨 위 요소를 그린다. 내용(`Content`)만 그리면 여백만큼 밀려 잘린다.
