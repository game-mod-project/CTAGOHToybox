AI가 이 명령을 PowerShell 도구로 실행하므로 `Bash(...)` 규칙은 맞지 않는다(이미 있는 `Bash(git worktree:*)`가 있어도 막혔다). auto 모드에서도 이런 좁은 허용 규칙은 자동 권한 검사보다 먼저 적용된다. 규칙은 명령마다 따지므로 AI는 이 명령들을 `;`로 잇지 않고 하나씩 실행한다.
  - 2026-10-21 세션 끝에 이 파일은 JSON이 깨져 있었다: 6행 `"PowerShell(gh pr merge *)"` 끝에 쉼표가 없다. 고치지 않으면 파일 전체(허용 규칙 237개 포함)가 적용되지 않을 수 있다. 권한 규칙이라 AI는 고치지 않았다.

## 모드가 갱신되면 (2026-10-21에 한 순서)

게임을 끈 상태에서 한다(빌드는 실행 중이면 멈춘다).

1. 옛 추출본 이름 바꾸기(`_work/mods/<id>` → `<id>.old-<날짜>`, 대조용) → 모드 분석(`CLAUDE.md` "모드 분석". Fusion은 `-FallbackWorkDir @('_work\mods\2905667604','_work\vanilla')`) → `Get-ModSummary`(네 모드 모두) → `New-ModDoc`. `mods.psv` 갱신일·크기와 `notes.md` 숫자를 고친다.
2. `vision-preset --variant wot --classes --project editor/projects/월드워-차종.json --force`
3. `faction-preset --army ger --base editor/projects/월드워-차종.json --project editor/projects/강화-독일.json --force`(수정 내용 문서 `docs/14-faction-boost/ger.md`도 다시 쓴다) → `build --project editor/projects/강화-독일.json`
4. `spawn-menu build` → `l10n extract`(L1: 지워진 `cheat.po`·`mission/.po`는 `git restore`) → 새 항목 채우기 → `l10n check` → `l10n build` → `spawn-menu build`
5. 테스트, `real`, `real-spawn`.

`faction-preset`을 다시 돌리면 일괄 규칙의 id가 새로 생긴다(수정 내용은 같다). 내용이 같으면 빌드할 필요는 없다.
