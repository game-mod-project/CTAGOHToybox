# 스폰 메뉴 대체 설계 (하위 프로젝트 C)

2026-10-17. 상태: 구현 끝(2026-10-17, `feat/spawn-menu`). 게임 안 동작은 미확인. 조사 근거는 [`docs/13-spawn-menu-spike.md`](../../13-spawn-menu-spike.md)(같은 날, 파일만 조사)다. **사용자 결정**은 그렇게 표시했고, 표시가 없는 결정은 AI 판단(표시: AI 판단)이다. 게임 안 확인은 하지 않는다(사용자 2026-10-16). 그래서 파일로 확인하지 못한 것은 `미확인`으로 두고, 그 위에 올리는 기능은 실패해도 나머지가 돌아가게 나눈다.

## 왜

원래 요청(스펙 A 2번): "기존 Spawn Menu를 대체하는 모드 구조. 바닐라와 모드의 모든 유닛을 캠페인·컨퀘스트·스커미시 안에서 소환."

지금 켜 둔 Spawn Menu of MACE(3617250510)를 쓰며 사용자가 겪는 문제(사용자, 2026-10-17):

1. 메뉴가 세로로만 나와 스크롤이 길다. MACE·Fusion처럼 유닛이 많으면 끝없이 길어진다.
2. 국가·플레이어(소속) 고르기가 토글이라 번거롭다.
3. 바닐라 말고 모드 유닛을 자동으로 가져오지 못한다(조사: Wunderwaffe 차량 204개 중 0개, 모드 보병 거의 없음).
4. 소환 말고 옵션이 부족하다(자원, 무적, 유닛 레벨, 지원 폭격 등).
5. 컨퀘스트·캠페인에서 아군 부대 카드가 없거나 다 쓰면 Spawn Menu도 같이 사라지거나 처음부터 뜨지 않는다.

조사에서 더 나온 문제: Spawn Menu of MACE가 맨 뒤에 로드되면서 Auto Medic의 캠페인 미션 수정 70개(`(include "/map/nikral's trigger.mi")`)와 MACE의 2026-09 컨퀘스트 스크립트(`dcg_script.inc`, `mace_scripts.inc`)를 2026-07 사본으로 덮는다(spike "지금 계층과의 충돌").

## 성공의 모습

- 전투 중 원하는 유닛을 **전차 → 중전차 → 티거 → 배치** 정도의 클릭으로 놓는다(사용자가 그린 흐름).
- 국가와 소속은 처음에 자동으로 정해지고(국가 = 그 판에서 플레이어가 고른 국가, 소속 = 내 소속), 원할 때만 바로 고르는 단추로 바꾼다(사용자 결정).
- 켜 둔 모드를 바꾸면 명령 한 번으로 메뉴를 다시 만든다. 손으로 목록을 적지 않는다.
- Spawn Menu of MACE를 꺼도 지금 할 수 있던 것은 다 된다. 그리고 다른 모드의 맵 수정을 덮지 않는다.

## 목표

1. **새 스폰 모드를 편집기가 생성한다.** Spawn Menu of MACE를 대체한다(사용자는 그 모드를 끈다).
2. **스커미시: 게임의 구매 창을 쓴다**(사용자 결정, 2026-10-17 "그대로 진행"). 왼쪽으로 펼쳐지는 격자 화면(`interface.pak!layout/views/scene/component/GameUnitSpawnView.xml`, `GridPanel id="unit_container"`)을 쓰도록 전 유닛 로스터를 만든다.
3. **캠페인·컨퀘스트(그리고 스커미시의 보조 메뉴): 미션 증원 창 메뉴를 쓴다.** 단계를 나눠 세로 스크롤을 줄인다.
4. **옵션**(사용자 요청 4번, 범위는 아래 "옵션"): 무적, 경험치 최대, 찍은 자리 폭격(소·중·대), 자원.
5. **메뉴가 사라지지 않게 한다**(사용자 요청 5번). 고쳐지는지는 확인할 수 없다(아래 "위험").
6. **맵 사본은 지금 계층의 이긴 판에 한 줄만 붙인다.** 다른 모드의 맵·스크립트 수정을 덮지 않는다.

## 하지 않는 것

- 게임 실행 파일·게임 폴더·창작마당 폴더의 파일을 고치지 않는다.
- 게임을 띄워 확인하지 않고, 게임 안 확인을 제안하거나 백로그에 만들지 않는다.
- 위장(도색) 바꾸기 단추는 다시 만들지 않는다(사용자가 요청하지 않음. AI 판단). Spawn Menu의 `debug.inc` 기능은 이 모드에 넣지 않는다.
- 한글 메뉴 글자는 이 프로젝트에서 하지 않는다. 메뉴 글자는 영어로 두고, 한글화는 P10(별도 세션)이 맡는다(AI 판단).
- Lua 스크립트를 새로 쓰지 않는다. 필요한 기능은 미션 스크립트(`.mi` 트리거)와 로스터(`.set`)로만 한다.

## 실패로 보는 것 (기술적으로 돌아가도)

- 다른 켜 둔 모드(Auto Medic, MACE, Wunderwaffe)의 맵·스크립트·로스터 수정을 옛 사본으로 덮는다.
- 손으로 목록을 고쳐야 모드 유닛이 들어간다.
- 메뉴 생성 때문에 출력 모드(`mod/CTAToybox`, 스탯 편집기 빌드)가 깨지거나, 두 모드가 같은 경로를 서로 덮는다.
- 정의를 찾지 못하는 유닛 이름이 메뉴에 들어가 게임이 꺼진다(2026-10-17의 `define not found`·`pattern not found` 같은 일).

## 구조

### 모드 폴더 (AI 판단)

- 새 모드 폴더 `mod/CTAToyboxSpawn/`(이름 `CTAToybox Spawn`, `mod.info` 버전 필드 `"any"`)에 생성한다. 스탯 출력 모드 `mod/CTAToybox`와 섞지 않는다. 스탯 빌드의 목록 파일(`.ctatoybox-build.json`)이 지우고 쓰는 범위와 겹치지 않게 하려는 것이다.
- 게임에 연결하는 방법(정션 `mods\CTAToyboxSpawn`)과 로드 순서는 사용자가 정한다. 문서에는 "모든 다른 모드보다 뒤, Spawn Menu of MACE는 끈다"를 권장으로 적는다.
- 같은 경로를 두 출력 모드가 함께 쓰면 생성을 멈추고 겹치는 경로를 보고한다.
- 생성물은 스탯 빌드처럼 목록 파일(예: `.ctatoybox-spawn.json`)로 관리해, 다시 생성할 때 이전 생성물만 지운다. git 추적 여부는 스탯 빌드의 P6 결정(생성물도 커밋)을 따른다.

### 명령 (AI 판단)

- 명령줄: `dotnet run --project editor/CtaToybox.Cli -c Release -- spawn-menu build [--out <폴더>] [--force]`. 기본 출력은 `settings.json`에 새 키(예: `spawnModDir`)로 둔다. 게임이 실행 중이면 `--force` 없이는 쓰지 않는다(스탯 `build`와 같은 규칙).
- `spawn-menu preview`: 쓰지 않고 무엇이 생기는지(맵 수, 유닛 수, 단추 수, 건너뛴 유닛과 이유)만 보고한다.
- 앱 화면은 이 프로젝트 범위 밖이다(명령줄만). 필요하면 나중에 백로그로.

### 입력

- 편집기가 이미 아는 계층(바닐라 → 켜 둔 모드, `sources`가 보여 주는 순서)과 유닛 색인(`units`, 이긴 판 기준).
- 맵 `.mi`와 로스터 `.set`은 지금 색인 범위 밖이다. 계층마다 pak과 낱개 파일에서 읽어 경로별 이긴 판을 고르는 기능이 필요하다(같은 경로는 나중 모드가 이기고, 낱개가 pak을 이긴다. `docs/07-stat-editor/ingame-check.md` 47·79·99행).
- 생성 대상 계층에서 **Spawn Menu of MACE(3617250510)와 원래 Spawn Menu(3295913567)는 뺀다**. 그 모드의 맵 사본을 "이긴 판"으로 잘못 고르지 않으려는 것이다. 그 모드에만 있는 보급 상자 `inf_crate_<진영>_weapon.def` 5개도 이 모드에 들어가지 않는다(AI 판단. 필요하면 나중에 같은 꼴로 생성).
- 스폰 모드 자신(`spawnModDir`)도 입력 계층에서 뺀다. 지금 `GameProfile.PlanLayers`는 스탯 출력 모드 하나만 빼므로, 뺄 폴더 목록으로 넓힌다(AI 판단).
- **스탯 출력 모드(`mod/CTAToybox`)는 입력에 넣는다**(AI 판단). 게임에서 스폰 모드보다 앞에 로드된다고 전제하고, 그 모드가 바꾼 정의와 사본 유닛도 메뉴에 들어가게 한다. 스탯 모드를 다시 빌드하면 스폰 모드도 다시 생성해야 한다(명령이 스탯 빌드 목록 파일의 시각이 더 새로우면 경고한다).
- **소환할 유닛 고르기**(AI 판단): 유닛 색인의 종류 `tank`·`cannon`·`car`(색인이 이미 파괴 모델·잔해·더미를 `vehicle-other`로 따로 둔다)와 로스터에 이름이 나오는 정의만 넣는다. 항공기는 로스터·Spawn Menu 목록에 이름이 나오는 정의만 넣는다. 나머지 `vehicle-other`는 넣지 않는다.
- **종류 나누기**(AI 판단, 앞에 있는 규칙이 이긴다): ① 그 정의가 로스터에 있으면 `b()` 값(`tanks`·`vehicles`·`empl` 등) ② 전차는 정의 폴더 이름의 `tank_light`·`tank_medium`·`tank_heavy`(바닐라·MACE 꼴) ③ 구축·자주포는 폴더·이름에 `td`·`stug`·`jagd`·`gmc`·`spg`·`sau`·`su_` 등이 있으면 ④ 그래도 모르면 `기타`. 규칙은 `editor/spawn/categories.psv` 같은 손으로 고치는 파일에 두어 사용자가 고칠 수 있게 한다.

## 스커미시: 구매 창 로스터 (사용자 결정)

근거: 구매 창은 로스터 `set/multiplayer/units/<시기>/units_<국가>.set`으로 채워진다. 유닛마다 `b()`(종류 단추), `{cost}`, `cd()`·`ci()`(첫 대기·재구매 대기), `cp()`를 적는다(`set/multiplayer/units/settings.set` 1–44행). MACE는 `b(tanks)` 367줄, Wunderwaffe는 550줄을 이미 로스터에 넣는다.

- **퍼지는 범위**: 이 로스터는 스커미시 계열 멀티 모드(battle_zones, frontlines, ammunition, evacuation 등)가 함께 쓴다. 모두 비용 0이 되는 것을 받아들인다(AI 판단: 사용자는 이 모드들을 스커미시로 쓴다). 컨퀘스트는 따로 `set/multiplayer/units/conquest/`를 쓰므로 바꾸지 않는다.
- **대상**: 지금 계층의 이긴 로스터 파일들(시기 `early`·`mid`·`late`, 국가 `ger`·`rus`·`usa`·`eng`·`fin`, 그리고 모드가 더한 국가·시기). 각 항목을 그대로 두고 값만 바꾼다. 분대 구성(승무원·분대원)은 원래 항목 것을 그대로 쓴다.
- **값**(사용자 결정): 비용 0 MP, CP 0, 대기 0, 구매 횟수 제한 없음. 설정으로 "원래 비용 유지"를 고를 수 있게 한다.
- **로스터에 없는 차량**: 유닛 색인의 전차·포·차량 가운데 그 국가 로스터 어디에도 없는 것은 국가별 기본 승무원으로 새 항목을 만든다(바닐라 로스터의 같은 종류 항목 꼴, 예: `squad_vehicle2_doctrine ... crew1(tankman...)`. 정확한 매크로 선택은 구현 계획에서 바닐라 예로 정한다). 국가는 `ArmyIndex`(로스터 `side()`)와 폴더로 정한다. 국가를 정하지 못하면 넣지 않고 보고한다.
- **종류 단추**(사용자 결정, 2026-10-17): 보병 분대 / 보병 낱개 / 거치 화기·포 / 차량 / 경전차 / 중형전차 / 중전차 / 구축·자주포 / 항공기·지원. 기본 단추 6개(`inf1`, `inf2`, `empl`, `vehicles`, `tanks`, `doctrine`) 밖의 새 단추가 게임에서 받아들여지는지는 `미확인`이다. 단추 그림은 `interface/scene/unit_icon/<단추>(<국가>)_00~03.tga` 이름으로 찾는다(바닐라 `doctrine(ger)_00.tga` 등). 그래서 생성기는 두 판을 낸다:
  - 기본: 새 단추 + 그림(바닐라 `tanks(<국가>)` 그림을 복사해 이름만 바꾼다. AI 판단).
  - 대체 판(`--basic-buttons`): 기본 6개만 쓴다. 경·중형·중전차는 `tanks`에 차례로 넣는다.
- 격자는 유닛 수에 따라 3열에서 6~9열까지 늘어난다(사용자가 게임에서 본 것. 파일에는 `cols="3"`만 있다).
- 이 창으로는 내 국가·내 소속만 산다. 다른 국가 유닛, 아군 AI·적 소속, 옵션은 아래 증원 창 메뉴가 맡는다. 스커미시에서도 증원 창을 켠다(Spawn Menu의 `SceneGameView.xml` 204행과 같은 방식).
- 봇(AI 상대)이 이 로스터의 비용 0을 쓰는지는 `미확인`이다. 봇 구매는 Lua 편성표(`script/multiplayer/units/<진영>/`)가 고른다는 것만 알고 있다(`docs/02` 128행).

## 캠페인·컨퀘스트: 증원 창 메뉴

### 붙이는 방식 (Spawn Menu와 같음, spike 근거)

- 맵 `.mi`마다, 지금 계층에서 **이긴 판**을 바이트 그대로 가져와 `{mission ...}`의 닫는 괄호 앞에 `(include "/map/ctatoybox_spawn/menu.mi")` 한 줄만 붙인다(이름은 AI 판단). 다른 줄은 바꾸지 않는다. `.inc` 등 맵의 다른 파일은 복사하지 않는다(이긴 판이 그대로 쓰이게).
- 대상 맵: 캠페인 `map/single/**/0.mi`(바닐라 pak 전체와 모드), 멀티 `map/multi/**/*.mi`(컨퀘스트 `campaign_capture_the_flag.mi`, `battle_zones.mi`, `ammunition.mi`, `evacuation.mi`, `frontlines.mi` 등). Spawn Menu는 캠페인 91·멀티 389개를 덮었다. 이 생성기는 계층에 있는 것을 모두 덮고 수를 보고한다.
- `.mi`가 이미 같은 include를 가지고 있으면 두 번 붙이지 않는다.
- 게임 패치나 모드 갱신으로 맵이 바뀌면 다시 생성해야 한다(문서에 적는다).

### 메뉴 파일 `menu.mi`의 내용 (Spawn Menu의 `cheat.mi` 구조를 따름)

`;{mission`으로 시작하는 조각이고, 미션 블록 안에 들어간다. 구성(spike "`cheat.mi`의 구조"):

- `{Helpers {event ...} {zone ...} {reinforcements ...} {vars ...} {functions ...} {triggers ...} {waypoints ...}}`.
- 대기 구역: 맵 밖 좌표의 보병·차량 구역과 웨이포인트(Spawn Menu는 77777·88888). 놓을 자리 웨이포인트는 단추의 `{waypoint ...}` + `{previewEntity ...}`로 고르게 한다(Spawn Menu `cheat.mi` 51909–51920행 꼴).
- 차량: 트리거가 `{"spawn" {entity "<정의 이름>"} {waypoint ...}}`로 만들고, 승무원을 붙이고, 소속·AI를 정한 뒤 `{"placement" ... {target_waypoint ...}}`로 옮긴다(`cheat.mi` 72434–72514행, 함수 `"vk c"` 59338행).
- 보병은 **분대 단위**로 부른다(사용자 결정). 메뉴 항목은 로스터의 분대 항목이고, 이름은 틀이 만드는 `<name>(<side>)`(예: `squad_ersatz_gren_late_all(ger)`)다. 분대 틀이 병종을 `{content "mp/%side/%period/%c1 …"}`로 만든다(`docs/07-stat-editor/README.md` 86행, `docs/09-modding-sources.md` S4). 바닐라+MACE+Wunderwaffe 스커미시 로스터의 보병 분대·단독 항목은 1,151개다(국가·시기·이름 기준).
- **분대 정보는 로스터에 있는 것을 그대로 가져온다**(사용자 결정). 분대 이름·구성(병종·인원)·장비를 새로 정하거나 고치지 않는다. 메뉴 항목은 로스터의 보병 분대(`b(inf1)`)와 단독 보병(`b(inf2)`) 항목 그대로다.
- 그 분대를 미션 안에서 실제로 나오게 하는 수단(로스터 이름으로 바로 부르기가 되는지, 안 되면 바닐라 증원처럼 숨겨 둔 병사를 복제하는지. 바닐라 예: `map/single.pak!single/00-bootcamp/04_reinforcements-offmap-support/0.mi` 19145행부터 `{clone}` `{make_squad}`)은 구현 계획에서 정한다. 어느 수단이든 분대 구성은 로스터 항목과 같아야 한다.
- 승무원: 차량의 로스터 항목에 있는 승무원 병종을 쓰고, 로스터에 없는 차량은 국가별 기본 승무원(전차병 + 전차장)을 쓴다(Spawn Menu는 태그 `tkm` 4명 + `tkcom` 1명).
- 단추 글자·그림: 게임의 유닛 설명 `desc/entity/<이름>`, 분대 `desc/squad/<분대>`와 그 아이콘을 그대로 쓴다(`cheat.mi` 51909–51920행, 48680–48692행). 아이콘이 없는 유닛은 종류 그림으로 대신한다(AI 판단).

### 메뉴 단계 (사용자 결정: 흐름 / AI 판단: 구체 단추)

증원 창은 한 번에 7개가 보이는 세로 목록이다(`GameUnitReinforcementView.xml`의 `StepScrollPane visibleElements="7"`). 단계는 이렇다:

1. **첫 화면**(맨 위 단추 `Spawn` 하나만 항상 보임 → 누르면 펼침): `국가: <지금 국가>` · `소속: <지금 소속>` · 보병 · 거치·포 · 차량 · 전차 · 항공기 · 지원(폭격) · 도구.
2. **종류 화면**: 전차 → 경전차 / 중형전차 / 중전차 / 구축·자주포. 보병 → 분대 / 낱개.
3. **유닛 화면**: 한 화면에 최대 N개(기본 21개 = 7칸 × 세 번 내림. AI 판단). 넘으면 계열 묶음(같은 정의 폴더 이름 앞부분, 예: 티거 계열)을 한 단계 더 두고, 그래도 넘으면 `다음 ▶`·`◀ 이전` 단추로 나눈다.
4. **배치**: 단추를 누르면 놓을 자리를 찍는다.

모든 화면에 `◀ 뒤로`와 `처음` 단추를 둔다. 단추 표시·숨김은 미션 동작 `"reinforcement" {operation show|hide}`로 바꾼다(바닐라 미션 각 479·491회).

### 국가와 소속 (사용자 결정)

- **국가 기본값**:

- 지금 Spawn Menu의 게임 안 기록(`docs/07-stat-editor/ingame-check.md`):

  - 목록 아래쪽 항목은 잘 눌리지 않는다(266행).

## 메뉴가 사라지는 문제 (사용자 요청 5번)

- 원인은 파일로 알 수 없다(`미확인`). 증원 창은 화면 조건(`enableif`)으로 켜진다. 바닐라 `SceneGameView.xml`은 편집기·싱글·협동에서만 켜고, Spawn Menu는 멀티(`gameclient.master`)와 컨퀘스트(`game.campaign and gameclient.master`)에도 켰다(204·212·219행).
- 대책(AI 판단, 효과는 확인할 수 없음):
  1. `SceneGameView.xml`에서 증원 창을 세 화면 묶음 모두에 조건 없이 둔다.
  2. 맨 위 `Spawn` 단추는 `{count -1}`(무제한)로 두고, 시작할 때와 짧은 주기로 `"reinforcement" {operation show}`를 다시 건다. 미션 스크립트가 숨겨도 다시 나타나게 하려는 것이다.
- `SceneGameView.xml`도 이긴 판을 바탕으로 이 변경만 더한다(지금은 MACE·AM·Wunderwaffe가 이 파일을 내지 않으므로 바닐라 판. 생성 때 다시 확인).

## 검증 (게임 밖에서만)

생성기 테스트(`editor/CtaToybox.Core.Tests`에 지금 꼴 `T.Eq`로, `Suites.All` 등록):

- 맵 사본 = 이긴 판 + include 한 줄(바이트 비교). 이긴 판이 Spawn Menu 계층이 아니다.
- `menu.mi`·로스터·`SceneGameView.xml`이 SDL 파서·XML 파서로 읽힌다(왕복).
- 메뉴와 로스터의 모든 `entity` 이름과 병종 경로가 계층 안의 정의로 풀린다(대소문자 무시). 못 푸는 것은 넣지 않고 보고한다.
- 단추의 `eventStart`마다 트리거가 하나 있고, 트리거마다 이벤트가 있다. 한 화면의 단추 수가 한도를 넘지 않는다.
- 두 출력 모드가 같은 경로를 쓰지 않는다.
- 실제 파일 검사(`-- real`): 지금 계층에서 생성해 위 검사를 모두 돌리고 수(맵, 유닛, 건너뜀)를 보고한다.
